## CAP-003: Cost-aware model routing

Routes a request cheap-first, verifies the cheap answer, escalates only on failure -- measured at 42.4% of always-strong spend at equal accuracy against a capability-modelled benchmark.

- **symbol:** `omnex.router.router.Router`
- **contract:** Router.route() returns a RoutedCompletion carrying which tier actually answered and what the same request would have cost on the reference tier.
- **dependencies:** omnex.llm.LanguageModel, CAP-001
- **security requirements:** A verifier must not itself be escalated past what the routing policy allows.
- **evidence:** E4_INTEGRATED — 3 test file(s) and 2 other production module(s) reference 'Router'
- **operational/production/outcome evidence:** E5_UNKNOWN_NOT_OBSERVABLE — requires evidence from a running deployment (traces, an operator, a payment); this repository has none, matching state_map.py's gate 5_production, which is UNKNOWN for the same reason
- **test files (3):** `engine/tests/test_node_links.py`, `engine/tests/test_node_map.py`, `engine/tests/test_router.py`
- **integrated by (2):** `engine/src/omnex/graph/runtime.py`, `engine/src/omnex/router/__init__.py`
- **limitations:** The 42.4% figure is measured against omnex.llm.fakes.CapabilityModel, a deterministic stand-in whose capability-is-monotone-in-tier assumption does not capture every real-provider failure mode.
- **known risks:** A verifier that is too lenient makes the router look cheaper than it is by accepting wrong cheap answers; break_even() is three-valued specifically so an under-measured verifier reads UNKNOWN rather than a false PASS.
- **economic relevance:** Directly: this is the single largest per-call cost lever the platform has.

## CAP-005: Injection fence

## CAP-006: MCP per-tool permission scoping

A registered tool can require a named permission; an unauthorized tools/call is refused with the identical error and payload shape as calling a nonexistent tool, so a caller without a permission cannot learn the tool exists.

- **symbol:** `omnex.mcp.server.McpServer`
- **contract:** McpServer.available_to(granted) filters both tools/list and tools/call identically; granted=None stays fully unrestricted so no caller loses a tool it never opted into losing.
- **dependencies:** none declared
- **security requirements:** An out-of-scope tool call must never return a distinguishable error from a nonexistent one.; required_permission is never read from or written to the wire.
- **evidence:** E4_INTEGRATED — 2 test file(s) and 1 other production module(s) reference 'McpServer'
- **operational/production/outcome evidence:** E5_UNKNOWN_NOT_OBSERVABLE — requires evidence from a running deployment (traces, an operator, a payment); this repository has none, matching state_map.py's gate 5_production, which is UNKNOWN for the same reason
- **test files (2):** `engine/tests/test_factory.py`, `engine/tests/test_mcp.py`
- **integrated by (1):** `engine/src/omnex/mcp/__init__.py`
- **limitations:** Permissions are a flat frozenset[str], not a role hierarchy or wildcard system -- deliberate, since nothing in this codebase yet has more than one caller identity.
- **known risks:** A future caller-identity system with roles would need to flatten roles to a permission set before calling available_to(), and a buggy flattening could over- or under-grant.
- **economic relevance:** None directly; this is an access-control capability, not a priced one.

## CAP-008: Eval regression gate

Blocks a deploy on any case that passed and now fails, never on the mean -- because a flat aggregate hides five regressions behind five simultaneous improvements.

- **symbol:** `omnex.evals.runner.Gate`
- **contract:** Gate.decide() compares a run to its baseline case-by-case and refuses to compare across a changed suite fingerprint.
- **dependencies:** CAP-004
- **security requirements:** none declared
- **evidence:** E4_INTEGRATED — 3 test file(s) and 4 other production module(s) reference 'Gate'
- **operational/production/outcome evidence:** E5_UNKNOWN_NOT_OBSERVABLE — requires evidence from a running deployment (traces, an operator, a payment); this repository has none, matching state_map.py's gate 5_production, which is UNKNOWN for the same reason
- **test files (3):** `engine/tests/test_evals.py`, `engine/tests/test_factory.py`, `engine/tests/test_state_map.py`
- **integrated by (4):** `engine/src/omnex/evals/__init__.py`, `engine/src/omnex/evals/judge.py`, `engine/src/omnex/factory/__init__.py`, `engine/src/omnex/factory/gates.py`
- **limitations:** The default metrics are deterministic and in-process; judge_quality() in judge.py is a separate, non-gating metric by design (variance between runs would make a noisy gate teach a team to disable it).
- **known risks:** Editing an expected answer and re-running looks identical to a real improvement unless the suite fingerprint is checked first -- which is why a fingerprint mismatch raises rather than silently comparing.
- **economic relevance:** Indirect: this is what stands between a bad model swap and a live regression a customer sees.
